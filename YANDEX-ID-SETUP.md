# Вход через Яндекс ID — как включить

Код входа и привязки Яндекс ID уже в проекте, но **по умолчанию выключен**:
кнопки «Войти через Яндекс ID» / «Привязать Яндекс ID» не показываются, а
`/api/auth/yandex/callback` отвечает ошибкой `not_configured`. Включается всё
из админ-панели, без пересборки образа.

## Что уже есть

| Компонент | Где |
|-----------|-----|
| OAuth 2.0 / PKCE клиент Яндекс ID | `src/lib/yandexId.ts` |
| Создание аккаунта, привязка, сессия | `src/lib/yandexAccount.ts` |
| Callback | `src/app/api/auth/yandex/callback/route.ts` |
| Статус/отвязка в профиле | `src/app/api/auth/yandex/route.ts` (GET/DELETE) |
| Кнопки на `/login` и `/account` | `src/components/AuthMethods.tsx` (рендерятся только если `/api/auth/providers` вернул `yandex: true`) |
| Таблица соответствий Яндекс ↔ аккаунт | `supabase/migrations/20260925010000_yandex_identities.sql` |
| Настройки провайдеров | Админ-панель → вкладка **«Авторизация»** (`/admin?tab=auth`) |
| Тесты | `scripts/tests/yandex-auth.test.mjs` |

Условие показа кнопки: **включено в админке** И **есть Client ID в формате
32 hex-символов** (из админки или из `YANDEX_ID_CLIENT_ID`) И на сервере задан
`SUPABASE_SERVICE_ROLE_KEY`.

## Шаг 1. Приложение в Яндексе

1. Откройте <https://oauth.yandex.ru> → «Создать приложение» (или
   <https://id.yandex.ru/security/app> → «Создать новое приложение»).
2. Платформа: **Веб-сервисы**.
3. **Callback URI:** `https://edringcolony.ru/api/auth/yandex/callback`
   (точный адрес показывается в админке в карточке Яндекс ID).
4. Доступы (группа «Яндекс ID»):
   - `login:email` — доступ к адресу электронной почты;
   - `login:info` — доступ к основной информации (имя);
   - `login:avatar` — доступ к аватарке.
5. Скопируйте **ClientID** (32 hex-символа) и **Client secret** — секрет
   показывается только один раз. Для веб-приложений секрет обязателен: без
   него обмен кода на токен не пройдёт.

## Шаг 2. Миграция БД

В Supabase Studio (SQL Editor) или через `psql` выполните
`supabase/migrations/20260925010000_yandex_identities.sql`. Таблица
`public.yandex_identities`: пишет только service role, пользователь видит
только свою строку.

## Шаг 3. Включение в админ-панели

`/admin` → вкладка **Авторизация** → карточка **Яндекс ID** → «настройки»:

1. Вставьте Client ID и Client secret → **Сохранить**.
2. Поставьте галочку **«показывать»**.
3. Статус в карточке должен стать «кнопка показывается».

Альтернатива для Client ID/секрета — переменные в `.env.production` сервиса
`web` (`YANDEX_ID_CLIENT_ID`, `YANDEX_ID_CLIENT_SECRET`) +
`docker compose up -d web`; галочка «показывать» в админке нужна в любом
случае. Значение из админки имеет приоритет над env.

Секреты из админки хранятся в таблице `billing_settings` (строка
`auth_providers`, только service role) и никогда не возвращаются в браузер —
показывается только факт наличия.

## Шаг 4. Проверка

1. В приватном окне откройте `/login` — появилась кнопка «Войти через
   Яндекс ID».
2. Войдите яндекс-аккаунтом → должно перекинуть на `/account`, в блоке
   «Способы входа» Яндекс ID: привязан.
3. Войдите обычным способом в другое досье → `/account` → «Привязать Яндекс
   ID» тем же аккаунтом → ожидаемая ошибка «уже привязан к другому досье»
   (слияния нет).
4. Логи при проблемах: `docker compose logs web | grep "Yandex Callback"`.

Типичные ошибки:

| Сообщение на сайте | Причина |
|--------------------|---------|
| «не настроен на сервере» | галочка снята, нет Client ID (32 hex) или нет `SUPABASE_SERVICE_ROLE_KEY` |
| «срок истёк или запрос подделан» | Callback URI в Яндексе не совпадает / cookie потеряна (другая вкладка, >10 мин) |
| «Не удалось завершить вход» сразу после выдачи прав | не задан/неверен Client secret — обмен кода на токен отклонён Яндексом |
| «Почта из Яндекса уже зарегистрирована» | по этой почте уже есть аккаунт — войти им и привязать Яндекс в профиле |
| «Не удалось создать сессию» | GoTrue отверг magic-link: проверьте, что версия GoTrue поддерживает `generateLink`/`verifyOtp(token_hash)` |

## Как выключить обратно

Снять галочку «показывать» в админке — кнопки исчезнут, callback начнёт
отвечать `not_configured`. Уже созданные привязки в `yandex_identities`
остаются; такие пользователи смогут войти другим привязанным способом
(при привязке Яндекса система не даёт отвязать последний реальный способ входа).

## Технические заметки

- Поток — OAuth 2.0 с PKCE (S256): `oauth.yandex.ru/authorize` →
  `oauth.yandex.ru/token` → `login.yandex.ru/info` (GET с заголовком
  `Authorization: OAuth <token>`). Токены Яндекса не хранятся: после входа
  выпускается обычная Supabase-сессия через админский `generateLink`.
- Если у яндекс-аккаунта нет подтверждённой почты (без `login:email`),
  аккаунт создаётся с техническим адресом `yandex-<id>@ya.edringcolony.ru` —
  письма туда никогда не отправляются.
- Аватарка берётся с `avatars.yandex.net/get-yapic/<id>/islands-200`.
