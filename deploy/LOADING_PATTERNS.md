# Паттерны погрузки

## Установка

1. Применить **после существующих миграций**
   `supabase/migrations/20261128090000_carrier_loading_patterns.sql`, затем
   `supabase/migrations/20261129090000_loading_pattern_members.sql`.
   Миграции создают таблицы шаблонов и участников с RLS и доступом только через
   серверный API. Существующие таблицы груза, банков, проектов и их RPC
   **не изменяются**. Миграция повторяемая; пользовательские данные не удаляет.
2. Развернуть сайт с этой веткой обычным способом.
3. Собрать/опубликовать обновление Colonial Helper штатным сборщиком bundle.
   В bundle должны присутствовать новые `loading_patterns.py` и
   `qt_loading_patterns.py` и `qt_loading_hud.py` (обычный рекурсивный сборщик
   включает их автоматически).

Миграция и публикация не выполняются автоматически от внесения кода/merge.
Без миграции API возвращает 503, а интерфейс сообщает о недоступности.
Откат приложения не затрагивает таблицу; удалять её для отката не требуется.

## Как пользоваться

- Сайт → **Архитектор → Погрузка**, `/architect/loading`.
- Создать паттерн, выбрать постройки и их количества; для поддерживаемой
  постройки можно включить вариант основного порта. Стоимость берётся из
  каталога Архитектора, а не из введённого клиентом списка товаров.
- Добавить авианосцы из «Мои / эскадронные» либо найти по ID/позывному.
  Указать тоннаж, выделенный **для этой погрузки**. Свободное место из карточки
  используется лишь как начальное значение; неизвестная вместимость требует
  проверки пилотом. Ноль допустим, максимальная выделенная вместимость — 60000 т.
- «Распределить автоматически» последовательно заполняет авианосцы в порядке
  списка, целыми тоннами. Всё, что не вместилось, остаётся в «Не распределено».
  Все назначения доступны для ручного редактирования.
- Изменение построек/авианосцев не запускает скрытое перераспределение:
  исправить назначения вручную, очистить или распределить заново. Избыточный
  тоннаж, неизвестные товары, отрицательные/дробные количества и дубли носителей
  сервер не принимает.
- Сохранить как **личный** или **публичный**. Личный доступен автору и приглашённым
  участникам; публичный можно открыть по ссылке или скопировать себе, но не
  редактировать от имени другого пилота. Публикуются цели/назначения,
  **не остатки банков и не разрешения доступа**.
- Helper → **Колонизатор → Паттерны погрузки** → выбрать → **Применить паттерн**.
  Можно показать все авианосцы или сфокусировать HUD на одном. Применение не
  отправляет игровых команд, не переводит товары и не меняет основной проект.
- Helper → **Оверлей** → включить **LOADING** (по умолчанию выключен).
  Штатно доступны перемещение, размер/пресеты, экран/якорь, шрифт,
  прозрачность, фиксация/сквозной клик, горячие клавиши, автоматическая
  видимость, импорт/экспорт раскладки и переключатели разделов содержимого.
  Для каждого авианосца показана карточка: название, 20 заполняющихся
  квадратиков прогресса, итоговый тоннаж и таблица **Товар / Загружено, т /
  Осталось, т**. Список всех авианосцев прокручивается; выбор одного носителя
  находится во вкладке применения.
- В LOADING переключатель **Оставшиеся товары / Все товары** скрывает или
  показывает завершённые строки, не меняя итогов и прогресса авианосца.
  Выбор сохраняется и синхронизируется с настройкой «Все товары (иначе только
  оставшиеся)» на вкладке **Оверлей**. По умолчанию показаны оставшиеся товары.
  Названия/итоги авианосцев, квадратные индикаторы, таблицу, переключатель,
  общую сводку и источник можно отдельно скрывать в настройках содержимого.
- Неизвестные остатки показаны как **?**, а не ноль. При частично известном
  инвентаре загруженный тоннаж помечен **≥**, незаполненные квадратики выделены
  контуром; это нижняя граница прогресса, не подтверждение отсутствия груза.
  У полностью загруженного авианосца в режиме оставшихся товаров показано
  «Нет оставшихся товаров»; авианосец без назначений остаётся с пустым
  индикатором и подписью «Нет назначенных товаров».

## Совместная погрузка и чужие авианосцы

1. Автор добавляет авианосец в паттерн, сохраняет назначения и в разделе
   **Участники паттерна** приглашает владельца авианосца по точному имени CMDR.
   Пилот должен быть зарегистрирован на сайте; неоднозначные имена отклоняются.
2. Приглашённый открывает паттерн в **Мои паттерны** на сайте. Там же отображаются
   собственные и совместные паттерны. Он выбирает свои авианосцы, для которых
   разрешает учитывать остатки, и нажимает **Принять приглашение и сохранить доступ**.
   Только приглашения недостаточно: без подтверждения общий груз не раскрывается.
3. Автор аналогично может открыть свои авианосцы для участников. Пилоты,
   которые лишь возят груз, принимают приглашение без выбора авианосцев.
   Участие не передаёт права редактировать или удалять паттерн.
4. После подтверждения автор и подтверждённые участники видят покрытие назначений
   выбранного авианосца и на сайте, и в Helper/LOADING. Helper использует тот же
   API; управление приглашениями и согласием находится на сайте. Достаточно
   обновить список **Мои паттерны**, выбрать и применить совместный паттерн.
5. Владелец может снять отметки и сохранить — доступ отзывается. Можно выйти
   из паттерна или быть удалённым автором. На следующем обновлении общие цифры
   исчезают. При смене владельца авианосца старое согласие больше не действует:
   сервер каждый раз проверяет текущее владение.

Согласие действует **только в конкретном паттерне** и только на отмеченные
личные авианосцы. Эскадронные права работают как прежде; офицер не может
выдать согласие от имени чужого владельца. Публичная ссылка, приглашение
без принятия и копия паттерна не дают новых прав на груз. Возвращается покрытие
назначенных товаров с ограничением по цели, не полный банк/избыток и не финансы.
Без учтённых сервером наблюдений по-прежнему будет `?` — приглашение само по
себе не получает актуальные данные из игры. Обновлять учёт должен владелец
через существующий механизм синхронизации Helper.

## Семантика прогресса и ограничения

- Это **покрытие назначений текущими учтёнными остатками**, не накопительный
  счётчик рейсов и не резервирование груза. Если товар выгрузили, покрытие
  уменьшается. Другие паттерны не резервируют/не списывают те же остатки.
- На каждый товар каждого носителя засчитывается не больше назначенного
  количества. Избыток на одном носителе не закрывает недостаток на другом.
- Недоступный авианосец или отсутствующее наблюдение по товару — `?`, а не 0.
  Нулевой остаток считается известным только при наблюдении товара или полном
  baseline. Частичные данные не превращаются в полный снимок банка.
- Источник — существующий серверный учёт груза (включая его ограничения
  полноты/актуальности). Cargo.json корабля, спрос рынка и маршрутные доставки
  отдельно не принимаются за содержимое банка. Текущее открытие страницы не
  является новым наблюдением инвентаря; показаны время проверки и метки учёта.
- Обычный доступ владельца/эскадрона сохраняется. Дополнительно подтверждённые
  участники могут видеть покрытие через явное согласие владельца в рамках
  паттерна (см. выше). Публичность сама по себе прав не расширяет.
  Финансы не возвращаются.
- Helper обновляет данные примерно раз в 30 секунд, когда открыта эта вкладка
  или включён применённый LOADING HUD. Само окно HUD сеть не опрашивает.
  При ошибке/утрате доступа старые цифры убираются; смена токена/сайта очищает
  приватное состояние, запоздалые ответы игнорируются. На диск сохраняется
  только выбранный ID паттерна, не содержимое банков.
- Применённый паттерн следует сохранённой версии автора, а не отдельной копии
  запуска. Чтобы зафиксировать собственные назначения публичного паттерна,
  сначала скопировать его себе на сайте. Сайт использует optimistic concurrency
  и не перезаписывает изменения из другого окна без сообщения о конфликте.
- Списки ограничены последними 100 собственными и 100 приглашёнными паттернами,
  публичный список — 100 паттернами; внутри одного — до 100 строк построек,
  20 уникальных авианосцев и 50 участников.
- RU/EN интерфейс готов; новые подписи остальных локалей пока используют
  английский fallback.

## Проверки

```sh
npm run typecheck
node scripts/run-tests.mjs loading-patterns architect bank-correction
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s uploader/tests -p 'test_loading*.py' -v
```

SQL проверяется настоящим PostgreSQL/PGlite: повторный запуск, ограничения,
service-only grants, RLS и удаление автора. API-тесты проверяют права,
отсутствие утечки банков, версионирование, лимиты и серверный расчёт;
jsdom-тесты — создание/копирование, смену списка/аккаунта и сохранение.
Native Qt-тесты требуют PySide6 и системные библиотеки Qt/OpenGL. В среде без
`libGL.so.1` они пропускаются; перед выпуском Helper нужен offscreen-прогон
в полноценной среде и smoke-test на Windows (особенно drag/resize,
click-through и поведение в игре).

### Результат проверки в текущей среде

- `npm run typecheck` — успешно.
- `node scripts/run-tests.mjs loading-patterns architect bank-correction` —
  **263/263**; из них loading-patterns — **31/31** (включая приглашения,
  согласие владельца, отзыв/смену владения, ограничения видимости,
  отсутствие утечки полного банка, SQL и UI совместного доступа).
- Словарь погрузки — **68 ключей × 7 локалей**, наборы ключей совпадают,
  пустых значений нет; новые подписи RU/EN, остальные — English fallback.
- `test_loading*.py` — **11 прошли, 7 native Qt пропущены**:
  отсутствует системная `libGL.so.1`. Дополнительные прогоны прежних
  overlay/colony Qt-наборов блокируются этой же зависимостью. Это не
  подтверждает работоспособность native UI на Windows — smoke-test обязателен.
- Общие `i18n-locale-parity`/`i18n-placeholders` находят существовавшие до
  изменения пропуски `admin.*` в базовых локалях и семь отсутствующих ключей
  карты/админки/загрузчика фото корабля. Проверено по `git show HEAD:...`;
  эти посторонние словари не исправлялись в рамках функции погрузки.
  Новый словарь `loadingPatterns.ts` подключён к обеим проверкам;
  собственные проверки его ключей, локалей и подстановок проходят.
