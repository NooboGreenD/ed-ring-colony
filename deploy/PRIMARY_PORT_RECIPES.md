# Фиксированные рецепты основных портов — каталог v5

## Источник и изменение

По уточнению владельца проекта основные орбитальные порты используют
фиксированные количества из таблицы Raven Colonial, без случайного разброса.
Рецепты перенесены **по каждому товару**, без масштабирования обычных
рецептов, без округления и без дополнительного запаса.

Зафиксирован источник:
https://github.com/njthomson/RavenColonialWeb/blob/114d213ad11be575c209f6890a3146fbf03cf875/src/assets/haul-costs.json

Данные: `src/lib/architect/primaryPortRecipes.ts`.
Независимый снимок источника для тестов:
`scripts/tests/fixtures/raven-primary-port-cargo.json`.
В тестах сравнивается весь словарь товаров, а не только общий тоннаж.
Сетевого обращения к Raven в расчёте нет.

| Основной порт | До исправления, т | Каталог v5, т |
| --- | ---: | ---: |
| Plutus, Vulcan, Dysnomia, Vesta, Prometheus | 21 795 | 21 835 |
| Nemesis (военный аванпост) | 11 885 | 21 835 |
| Coriolis | 68 825 | 70 533 |
| Asteroid | 68 825 | 70 533 |
| Orbis / Ocellus | 241 960 | 242 742 |
| Dodec | 273 410 | 269 924 |

Все шесть основных аванпостов используют `orbital-outpost-primary` из
Raven: в частности, **500 т алюминия, 6 660 т стали, 5 534 т титана,
4 508 т CMM**. Военный рецепт обычного Nemesis больше не используется
для основного Nemesis.

Для этих рецептов `approximate: false`; подсказки заменены на указание
фиксированного рецепта Raven. Наборы материалов обычных построек и их
стоимость не менялись.

### Отдельный случай: Zeus

В указанной таблице нет отдельного primary-рецепта планетарного Zeus.
Его прежняя помеченная оценка оставлена без изменения для совместимости
планов; она **не** объявлена фиксированным рецептом Raven. Подставлять
вместо неё обычный рецепт или придумывать новый точный список нельзя.

## Существующие планы и паттерны

- `CATALOGUE_VERSION` повышен с 4 до 5. Обычные планы/черновики используют
  существующее предупреждение об изменении каталога. Для обновления
  сохранённой серверной сводки старого плана его нужно открыть и сохранить.
- Требования паттернов погрузки пересчитываются текущим каталогом.
  Старые назначения могут включать товары, которых больше нет в рецепте,
  или превышать новую потребность. Это больше не приводит к 503 при
  просмотре списка или открытии старого паттерна.
- **Только при чтении строк со старой версией каталога** удаляются
  устаревшие товары и ограничиваются избыточные назначения в порядке
  списка авианосцев. Товары не перемещаются между авианосцами;
  новые/увеличенные потребности остаются явно нераспределёнными.
- Просмотр не изменяет БД. Веб-интерфейс и обновлённый Helper показывают
  предупреждение о пересчёте. Автор проверяет распределение и сохраняет
  паттерн, чтобы записать новые назначения и версию каталога 5.
- POST/PATCH по-прежнему строго проверяют текущие рецепты, вместимость,
  целые неотрицательные количества и уникальные авианосцы. Передача
  клиентом старой `catalogue_version` не обходит проверку.

## Развёртывание и проверки

Отдельная SQL-миграция не нужна. Развернуть сайт; обновление Helper
добавляет текст предупреждения для пересчитанного паттерна. Сам сервер
отдаёт новые требования и корректный прогресс также старому Helper.
Банки и наблюдаемые остатки не изменяются.

Проверки в этой ветке:

- `npm run typecheck` — успешно.
- `node scripts/run-tests.mjs architect loading-patterns bank-correction` —
  253/253 успешно, включая все товары первичных рецептов, планировщик,
  API, интерфейс и совместимость паттернов v4.
- Helper loading-pattern tests — 6 прошли, 3 native Qt пропущены из-за
  отсутствия PySide6 в текущей среде; Python compileall — успешно.
- Общие i18n-проверки: 49/52; три прежних падения касаются пропусков
  базовых ключей карты/админки/фото корабля и не относятся к этой правке.
  Новые ключи и подстановки проходят проверки.

Production-развёртывание и публикация обновления Helper этим изменением
не выполняются автоматически.
