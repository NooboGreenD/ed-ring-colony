# Личные сообщения: приватные вложения

Перед выкладкой применить штатным способом миграцию
`supabase/migrations/20261125090000_direct_message_attachments.sql`.
Она добавляет `messages.attachments` и **закрытый** bucket
`direct-message-files`. Её можно выполнять повторно. Приложению нужны
существующие серверные настройки Supabase, включая service-role ключ.
Ключ нельзя передавать браузеру.

Текстовые сообщения остаются совместимыми со старой схемой, но для вложений
нужна миграция и работающий Supabase Storage. Допустимы до пяти файлов,
каждый до 10 МиБ, суммарно до 20 МиБ (с запасом под multipart при стандартном
nginx-лимите 25 МиБ). Форматы перечислены в `src/lib/directMessages.ts`.
Произвольные исполняемые файлы, HTML и SVG не принимаются. Это проверка
формата/размера, не антивирусная проверка; не открывайте неизвестные файлы.

Файлы выдаются через авторизованный `/api/messages/{id}/attachments/{id}`:
проверяются участник диалога, запись сообщения и принадлежность пути файлу.
Публичные и долгоживущие подписанные ссылки не создаются. Ответы `no-store`;
обычные файлы скачиваются, разрешённые растровые изображения открываются по
кнопке предпросмотра. Внешние Markdown-картинки не загружаются.
Удаление сообщения отправителем через новый API удаляет и его объекты.
Если очистка Storage не удалась, либо строка удалена старым клиентом/каскадно,
может остаться закрытый объект: без строки сообщения API его не выдаст.
При обслуживании Storage такие сироты можно удалять после сверки путей с
`messages.attachments`; не открывайте bucket для решения ошибок загрузки.

## Проверка после выкладки

1. Два аккаунта-друга: отправить текст без перезагрузки, отключить WebSocket
   и убедиться, что отправка видна сразу, входящее появляется за ~10 секунд
   при открытой вкладке.
2. Проверить перенос Shift+Enter, форматирование, эмодзи, ошибки отправки
   (черновик/вложения сохраняются), быструю смену собеседника.
3. Отправить PNG/JPEG и PDF/ZIP; проверить предпросмотр/скачивание у обоих
   участников. Третий аккаунт и гость не должны получить файл по тому же URL.
4. Проверить длинный диалог на широком и узком экране: прокручивается
   область сообщений, поле ввода остаётся в ограниченном окне.

Автотесты: `node scripts/run-tests.mjs direct-messages friends-api squadron-bank`
и `npm run typecheck`. Тест SQL выполняется в PGlite, не в рабочей базе;
браузерную интеграцию с действующим Supabase нужно проверить отдельно.
