# Разовая прибавка к назначениям погрузки

Над матрицей `/architect/loading` добавлены поле целого количества тонн и кнопка
«Добавить +N т к заполненным ячейкам». Это разовая операция, а не настройка
автораспределения.

## Поведение

- Прибавляет N к каждой положительной ячейке на каждом носителе, в том числе
  скрытой поиском/категорией/фильтром нераспределённого. Нули и отсутствующие
  назначения не заполняет.
- Работает с вручную введёнными и автоматически распределёнными назначениями.
  Повторное нажатие снова прибавляет N. Пока назначений нет, кнопка недоступна.
- Проверяет **выделенную пользователем вместимость каждого носителя**. Это
  доступное место, указанное для паттерна, а не запрос всей приватной загрузки
  носителя. Нельзя увеличивать её автоматически ради запаса.
- Если места не хватает хотя бы на одном носителе, операция целиком отменяется.
  Сообщение содержит носитель, требуемый дополнительный объём, свободное место
  и недостачу. Назначения не меняются и паттерн не становится несохранённым.
- Автораспределение и очистка назначений убирают запас. При ручном обнулении
  ячейки убирается и её запас. Удаление носителя удаляет его запас.
- Как и остальные изменения назначений, прибавку нужно сохранить. До сохранения
  старый серверный прогресс скрыт с предложением сохранить изменения.

## Учёт и совместимость

`LoadingPattern.allocations` содержит итоговые цели, **включая** запас. Новое
необязательное поле `extras[carrierId][commodity]` хранит входящую в эту цель
добавку. Например, `allocations.steel = 12`, `extras.steel = 2` — это 10 т
основного назначения и 2 т запаса, а не 14 т.

Сервер проверяет целые количества, известные товары/носители, соответствие
метаданных (положительный запас требует положительного основного назначения),
ограничение основного назначения рецептом и итоговую вместимость. Неявный
перерасход без `extras` по-прежнему отклоняется. Требования построек не меняются.

- Общая цель погрузки = норма рецепта + сумма `extras`.
- Нераспределённая потребность = норма рецепта минус основные назначения.
  Дополнительные тонны на одном носителе не засчитываются вместо ещё не
  распределённой нормы другого.
- Прогресс носителя и строки `required` включают запас. Поэтому один только
  основной груз не даёт преждевременные 100%; неизвестные остатки остаются
  неизвестными, а не нулевыми.

Поле сохраняется в существующем JSON `definition`: миграция БД и изменение
рецептов/версии каталога не нужны. Нужен обновлённый API сайта; Helper уже читает
итоговые цели из его ответа, отдельное изменение протокола Helper не требуется.
Права редактирования/приватность остатков не меняются.

## Регрессии

`loading-extras.test.mjs` — +1/+2, повторное нажатие, round-trip, нули,
неизменность рецептов, проверка точной вместимости и атомарный отказ, строгая
валидация метаданных, прогресс и восстановление базового автораспределения.

`loading-patterns-ui.test.mjs` — реальный компонент: фильтры, сохранение,
очистка/автораспределение, ошибки вместимости и read-only.
`loading-patterns-api.test.mjs` — PATCH/GET и цели для Helper.
`test_loading_extras.py` — отображаемые цели/остатки Helper с запасом и
неизвестными остатками без Qt.

Playwright с production CSS проверяет прибавку, атомарный отказ и отсутствие
переполнения страницы, сохраняя проверки чередования строк и пяти ширин экрана.
