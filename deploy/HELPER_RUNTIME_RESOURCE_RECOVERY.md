# Helper 2.30.23: отсутствующий commodity_names.json

## Причина

Web-сборщик пакетов разрешал только `loading_goods.json`, хотя новый
`commodity_names.py` читает соседний `commodity_names.json` при импорте.
Python-сборщик уже включал этот файл, поэтому прежние тесты Python-сборки
не покрывали ошибку web-публикации. В присланном журнале запуск 2.30.23
останавливается с FileNotFoundError именно на этом JSON.

## Исправление

- Общая таблица module → resource управляет выбором JSON при серверной
  сборке, выборе каталога в админке и фильтрации пакета на сервере.
- Создание релиза и прямая публикация подписанного CI-пакета отказывают,
  если модуль есть, а его обязательного справочника нет. Отказ не меняет канал.
- Python-сборщик также больше не пропускает отсутствующий справочник молча.
- Тест проходит настоящий сбор исходников сайта → публикацию → подписанный
  манифест, blobs и ZIP. При наличии Python отдельно импортирует модуль
  названий товаров из распакованного ZIP в изолированном процессе.
- Launcher 1.5.1 очищает пути и импортированные модули неудачной установленной
  версии перед запуском встроенной копии. Раньше встроенный путь мог уже
  находиться в конце sys.path, и повторно запускался сломанный код.

## Восстановление / порядок выпуска (не выполнено автоматически)

1. Развернуть исправленный сайт, включая каталог `uploader` с обоими JSON.
2. Выпустить **новую** версию пакета (например, 2.30.24, если номер свободен).
   Не перезаписывать опубликованный 2.30.23: содержимое подписанной версии
   должно оставаться неизменным.
3. До продвижения проверить наличие `commodity_names.json` и
   `loading_goods.json` в манифесте и архиве; проверить запуск на Windows.
4. Обновиться до нового полного пакета через стартовый экран Helper. Если
   он недоступен, использовать Setup с заведомо полным встроенным пакетом
   и переустановку/восстановление **после** исправления канала обновлений.
5. Для доставки исправления аварийного запуска собрать и опубликовать новый
   базовый exe/Setup с launcher 1.5.1. Обычный пакет Python-модулей не заменяет
   загрузчик внутри уже установленного exe. Новая база не обязательна только
   ради добавления недостающего JSON в обычный пакет.

Не удалять настройки, токены и журналы пилота. Не исправлять подписанный
пакет произвольным JSON и не отключать проверку подписи/хешей. Логи пользователя
в репозиторий не включать. Эта ошибка не доказывает причины других ранее
наблюдавшихся зависаний или проблем запуска.
