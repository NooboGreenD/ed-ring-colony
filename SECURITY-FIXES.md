**Оставшиеся границы доверия:** автоматическое членство из журнала по-прежнему опирается на клиентский отчёт, как и до исправления. RLS защищает записи от пользователя без нужного site membership/permissions, но не доказывает подлинность игрового журнала. Если требуется защищать закрытые эскадрильи от ложного самоотчёта, нужен отдельный продуктовый поток подтверждения/приглашения либо проверенный внешний источник; нельзя считать это решённым одной RLS-миграцией.

Storage и metadata не составляют общую распределённую транзакцию. Неуспешный upload cleanup после ошибки БД пока остаётся best-effort; для гарантированной очистки при сетевых сбоях нужен отдельный reconciliation/cleanup job. Подтверждённая ошибка Storage.delete теперь явно возвращается клиенту и сохраняет metadata для retry.
