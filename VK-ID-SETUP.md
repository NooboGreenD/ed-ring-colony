# Вход через VK ID — как включить

Код входа и привязки VK ID уже в проекте, но **по умолчанию выключен**:
кнопки «Войти через VK ID» / «Привязать VK ID» не показываются, а
`/api/auth/vk/callback` отвечает ошибкой `not_configured`. Включается всё
из админ-панели, без пересборки образа.

## Что уже есть

| Компонент | Где |
|-----------|-----|
| OAuth 2.1 / PKCE клиент VK ID | `src/lib/vkId.ts` |
| Создание аккаунта, привязка, сессия | `src/lib/vkAccount.ts` |
| Callback | `src/app/api/auth/vk/callback/route.ts` |
| Статус/отвязка в профиле | `src/app/api/auth/vk/route.ts` (GET/DELETE) |
| Кнопки на `/login` и `/account` | `src/components/AuthMethods.tsx` (рендерятся только если `/api/auth/providers` вернул `vk: true`) |
| Таблица соответствий VK ↔ аккаунт | `supabase/migrations/20260923000000_vk_identities.sql` |
| Настройки провайдеров | Админ-панель → вкладка **«Авторизация»** (`/admin?tab=auth`) |
| Тесты | `scripts/tests/vk-auth.test.mjs` |

Условие показа кнопки: **включено в админке** И **есть числовой Client ID**
(из админки или из `VK_ID_CLIENT_ID`) И на сервере задан
`SUPABASE_SERVICE_ROLE_KEY`.

## Шаг 1. Приложение в VK ID

1. Откройте <https://id.vk.com/about/business/go> → «Создать приложение»,
   платформа **Web**.
2. Базовый домен: `edringcolony.ru`.
3. **Доверенный Redirect URL:** `https://edringcolony.ru/api/auth/vk/callback`
   (точный адрес показывается в админке в карточке VK ID).
4. Доступы: `email` (запрашиваем только его; при отказе аккаунт всё равно
   создаётся с технической почтой `vk-<id>@vk.edringcolony.ru`).
5. Скопируйте **ID приложения** (числовой). «Защищённый ключ» нужен только
   если приложение помечено как confidential — для Web-приложений с PKCE он
   обычно не требуется.

## Шаг 2. Миграция БД

В Supabase Studio (SQL Editor) или через `psql` выполните
`supabase/migrations/20260923000000_vk_identities.sql`. Таблица
`public.vk_identities`: пишет только service role, пользователь видит только
свою строку.

## Шаг 3. Включение в админ-панели

`/admin` → вкладка **Авторизация** → карточка **VK ID** → «настройки»:

1. Вставьте Client ID (и секрет, если есть) → **Сохранить**.
2. Поставьте галочку **«показывать»**.
3. Статус в карточке должен стать «кнопка показывается».

Альтернатива для Client ID — переменные в `.env.production` сервиса `web`
(`VK_ID_CLIENT_ID`, `VK_ID_CLIENT_SECRET`) + `docker compose up -d web`;
галочка «показывать» в админке нужна в любом случае. Значение из админки
имеет приоритет над env.

Секреты из админки хранятся в таблице `billing_settings` (строка
`auth_providers`, только service role) и никогда не возвращаются в браузер —
показывается только факт наличия.

## Шаг 4. Проверка

1. В приватном окне откройте `/login` — появилась кнопка «Войти через VK ID».
2. Войдите новым VK-аккаунтом → должно перекинуть на `/account`, в блоке
   «Способы входа» VK ID: привязан.
3. Войдите обычным способом в другое досье → `/account` → «Привязать VK ID»
   тем же VK → ожидаемая ошибка «уже привязан к другому досье» (слияния нет).
4. Логи при проблемах: `docker compose logs web | grep "VK Callback"`.

Типичные ошибки:

| Сообщение на сайте | Причина |
|--------------------|---------|
| «не настроен на сервере» | галочка снята, нет Client ID или нет `SUPABASE_SERVICE_ROLE_KEY` |
| «срок истёк или запрос подделан» | redirect URL в VK не совпадает / cookie потеряна (другая вкладка, >10 мин) |
| «Почта из VK уже зарегистрирована» | по этой почте уже есть аккаунт — войти им и привязать VK в профиле |
| «Не удалось создать сессию» | GoTrue отверг magic-link: проверьте, что версия GoTrue поддерживает `generateLink`/`verifyOtp(token_hash)` |

## Как выключить обратно

Снять галочку «показывать» в админке — кнопки исчезнут, callback начнёт
отвечать `not_configured`. Уже созданные привязки в `vk_identities`
остаются; такие пользователи смогут войти другим привязанным способом
(при привязке VK система не даёт отвязать последний реальный способ входа).

## Остальные провайдеры на вкладке «Авторизация»

- **Discord / Google / GitHub и другие GoTrue-провайдеры** — секреты
  настраиваются в окружении Supabase Auth (`GOTRUE_EXTERNAL_*`, см.
  `SELFHOST.md`), список разрешённых — `AUTH_OAUTH_PROVIDERS` сайта. Галочка
  в админке только скрывает/показывает кнопку; поля Client ID/Secret там —
  памятка (сайт их GoTrue не передаёт).
- **Яндекс ID, Telegram, Steam** — помечены как «план»: настройки
  сохраняются, кнопок нет до появления реализации (делать по образцу VK ID).
