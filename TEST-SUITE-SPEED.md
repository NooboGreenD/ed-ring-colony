# Скорость набора тестов

Набор вырос до 1200+ проверок, и `npm test` шёл **2 мин 15 с**. Разбор показал,
что время тратят не сами проверки: из 136 с последовательного прогона

* ~47 с — ожидание сети и базы в трёх файлах (тесты уходили в реальные запросы,
  которые в песочнице заканчивались таймаутом);
* ~13 с — повторная сборка одного и того же кода esbuild'ом внутри одного файла;
* остальное — последовательный прогон файлов: `node --test` берёт
  `availableParallelism() - 1` воркеров, то есть на двухъядерной машине
  (обычный CI-раннер и `docker build`) набор шёл строго по одному файлу.

После правок: **50 с** на том же железе, быстрый контур — **16 с**.

| Прогон | Было | Стало |
|--------|------|-------|
| `npm test` (всё, 1223 проверки) | 134,7 с | 49,8 с |
| `npm run test:quick` (1003 проверки) | — | 16,2 с |
| то же последовательно (`--test-concurrency=1`) | ~136 с | 90,5 с |

## Что сделано

### 1. Тесты больше не ходят в сеть и базу

Три файла теряли секунды на таймаутах реальных запросов:

| Файл | Было | Стало | Что мешало |
|------|------|-------|------------|
| `oauth-selfhost.test.mjs` | 21,6 с | 0,18 с | `visibleGotrueProviders` читал настройки из Supabase, `readMaintenanceCached` — признак техработ: два запроса по ~7 с на тест |
| `update-agent.test.mjs` | 10,5 с | 2,5 с | тест отказа `apply-smtp.sh` проживал рабочие паузы скрипта (2 с и 4 с между попытками); теперь `AUTH_TRIES=1`, `AUTH_HTTP_TRIES=1` |
| `architect-system-bodies-route.test.mjs` | 7,6 с | 0,15 с | `findSystemByName` подключался к Postgres и ждал таймаута соединения |

Проверяемое поведение не изменилось — подменены только внешние зависимости.
Это тот же принцип, что в [DOCKER-TESTS-HERMETIC-FIX.md](DOCKER-TESTS-HERMETIC-FIX.md):
тест обязан падать из-за кода, а не из-за недоступности сети.

### 2. Общий кэш сборок esbuild

`scripts/tests/helpers/bundle.mjs` — `bundleFile()` / `importBundle()`:

* сборка кладётся в `.cache/test-bundles/<hash>.mjs`, ключ — содержимое входа и
  опций сборки;
* пригодность кэша проверяется по размеру и `mtimeMs` каждого файла из
  `metafile.inputs`: изменился любой исходник, заглушка или опция — сборка
  пересобирается;
* заглушки (`next/link`, `next/server`, …) пишутся по стабильным путям, иначе
  ключ менялся бы на каждом прогоне из-за нового временного каталога;
* запись идёт через временный файл и переименование — параллельные воркеры не
  подхватят чужую недописанную сборку.

Главный выигрыш — внутри одного файла: раньше каждый рендер компонента
пересобирал страницу заново.

| Файл | Было | Стало |
|------|------|-------|
| `architect-ui.test.mjs` (25 рендеров) | 13,6 с | 10,5 с |
| `atlas-ui-dom.test.mjs` (16 рендеров) | 8,2 с | 6,5 с |
| `outfitting-ui.test.mjs` | 6,0 с | 5,1 с |

`.cache/` уже в `.gitignore` и `.dockerignore`. Побочно тесты перестали
создавать `.tmp-*` каталоги в корне репозитория.

Перевести свой файл на кэш:

```js
import { bundleFile } from './helpers/bundle.mjs';

const bundle = await bundleFile({
  entrySource: "export { default as Page } from '@/app/some/page';",
  stubs: { 'next/link': LINK_STUB, '@/lib/supabaseAdmin': DB_STUB },
  external: ['react', 'react-dom', 'react-dom/client'],
});
const mod = await import(bundle);
```

Остальные 21 файл со сборкой пока работают по-старому: они собирают по одному
разу и стоят меньше секунды.

### 3. Явная параллельность и быстрый контур

`npm test` теперь запускает `scripts/run-tests.mjs`:

* число воркеров — `TEST_CONCURRENCY` или `max(4, availableParallelism())`;
* `--quick` пропускает тяжёлые файлы. Тяжёлый файл определяется по его
  содержимому (импорт `jsdom` или запуск внешних процессов), а не по списку,
  который протухнет;
* аргументы после `--` передаются в `node --test`, а обычные слова работают как
  фильтр по именам файлов.

```
npm test                                 # весь набор (~50 с)
npm run test:quick                       # без jsdom и shell-интеграций (~15 с)
npm run test:list                        # файлы и их класс
node scripts/run-tests.mjs atlas ring    # только файлы про Atlas и кольцо
node scripts/run-tests.mjs -- --test-name-pattern="кольцо"
```

`test:galnet` больше не дублирует весь набор — он запускает только файлы
`galnet`.

## Почему число проверок не сокращали

Проверок 1223, и это не «вода»: одинаковых имён во всём наборе нет (единственное
совпадение — одноимённые тесты входа через VK ID и Yandex ID, они про разных
провайдеров), а 70 % времени давали восемь файлов из 105. Стоимость одной
проверки — доли миллисекунды; дорогими были стенды вокруг них (сборка, jsdom,
запуск shell-скриптов) и ожидание сети. Поэтому вместо удаления покрытия
убраны причины тормозов, а для частых правок добавлен быстрый контур.

Что осталось тяжёлым и почему это нормально:

| Файл | Время | Что делает |
|------|-------|------------|
| `update-script.test.mjs` | ~20 с | гоняет настоящий `deploy/update-project.sh` на временных git-репозиториях |
| `architect-ui.test.mjs` | ~10 с | 25 рендеров страницы в jsdom |
| `atlas-ui-dom.test.mjs` | ~6,5 с | 16 рендеров страницы Atlas в jsdom |
| `db-backup.test.mjs` | ~6,5 с | shell-интеграция резервного копирования |
